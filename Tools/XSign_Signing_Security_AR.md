# مراجعة التوقيع والحماية — XSign وFeather

المراجعة بتاريخ 2026-11-05. مرجع Feather الرسمي: الالتزام `31ab6de455f2a6108f6830e343dee826310c03be` من `claration/feather`. قاعدة XSign العامة المقروءة: `4c84bd39dde0e0a22f71d0756c2cf1153fe2765c`، مع الحفاظ على تحديث المصدرين والسيرفر المحلي المعدَّين سابقاً.

## أين يتم التوقيع فعلاً؟

| الجزء | Feather الرسمي | XSign بعد التحديث |
|---|---|---|
| توقيع Mach-O | داخل الجهاز عبر Zsign/OpenSSL؛ انظر `Feather/Utilities/Handlers/ZsignHandler.swift` | المحرك نفسه مضمّن داخل التطبيق ويُستدعى محلياً؛ لا يوجد رفع IPA أو المفتاح لخادم توقيع |
| السيرفر المحلي | Vapor لخدمة التثبيت | HTTP منفصل لتنظيم التوقيع، وHTTPS مؤقت لخدمة حزمة التثبيت إلى iOS. كلاهما يرتبط بـ`127.0.0.1` |
| شهادات HTTPS | Backloop للنقل المحلي | TLS 1.2 أو أحدث، تحديث تلقائي لحزمة Backloop والتحقق بثقة النظام. هذا اعتماد نقل خارجي منفصل عن محرك توقيع التطبيقات |
| تثبيت التطبيق | HTTPS أو InstallationProxy بحسب الطريقة | OTA عبر itms-services دون Pairing أو VPN. manifest على x-sign.web.app وIPA من HTTPS داخل الجهاز |

لا توجد علاقة بين استخدام مكتبة Zsign المفتوحة وبين الاعتماد على خدمة تطبيق تجاري يحمل اسماً مشابهاً. السيرفر الداخلي ليس محرك تشفير جديداً، ولا يزيد سرعة توقيع C++ تلقائياً؛ يفصل الطلبات ويحمي إدارة المهام. المصدر والتراخيص والاعتمادات الأصلية محفوظة.

## التغييرات الأمنية الفعلية

| الملاحظة المثبتة في الكود | المعالجة |
|---|---|
| حد الطابور القديم يعد المهام قبل قبول HTTP فقط؛ المهمة الجارية لا تُحتسب | حد 8 يشمل المسجَّلة والمنتظرة والجارية والنتائج غير المستلمة، مع منفّذ واحد. لا تتكرر المهمة عند إعادة POST |
| طلب HTTP يبقى مفتوحاً حتى انتهاء التوقيع | POST قصير يرجع 202؛ النتيجة تنتقل عبر continuation داخل العملية. إذا فُقد تأكيد HTTP بعد قبول المهمة تستعاد نتيجتها دون إعادة توقيع |
| رمز Bearer صالح لكل المسارات طوال التشغيل | HMAC-SHA256 بمفتاح 256 بت لكل تشغيل للسيرفر، مرتبط بالطريقة والمضيف والمسار. مكتبة CryptoKit/Crypto تتحقق من المصادقة |
| أسطح إدخال غير ضرورية | طلب بلا body، رفض Origin وHost غير الصحيح وترويسات الضغط والتحويل، تعطيل فك ضغط الطلبات وHTTP/2 وpipelining. لا توجد مسارات ملفات أو تصدير على سيرفر تنظيم التوقيع |
| خادم دائم وعدد خيوط افتراضي مرتفع | حلقة أحداث واحدة وخيط عمل واحد؛ يغلق بعد 30 ثانية خمول ويُنشئ مفتاحاً جديداً عند بدء جديد. إيقافه لا يقطع مهمة جارية |
| Zip 2.1.2 المستخدمة لفك IPA مرتبطة بالثغرة CVE-2023-39135 | أزيلت المكتبة من اعتماد التطبيق واستُبدلت بـZIPFoundation 0.9.20 مثبتة بالالتزام. فك التدفق محدود ويفحص المسارات والحجم الفعلي وCRC |
| إمكانية خروج مسار الأرشيف أو المرور برابط رمزي أو الكتابة فوق ملف | فحص جميع الإدخالات قبل الكتابة؛ رفض `..` والمسارات المطلقة والشرطات العكسية والروابط الرمزية وتعارض الملف/المجلد والأسماء المتعارضة. مجلد استخراج جديد يُحذف عند الفشل |
| احتمال استنزاف الذاكرة/القرص | فك بكتل 1 MiB، حد 100 ألف إدخال، حد 8 GiB للملف و16 GiB للإجمالي، وحجز 256 MiB للقرص. تُراقب الأحجام أثناء الفك، ولا تُصدَّق أحجام ZIP وحدها |
| استيراد/تصدير الشهادة عبر رابط يحمل المفتاح وكلمة المرور | أُوقفت واجهتا URL للشهادات. الاستيراد من منتقي الملفات فقط؛ لا يُنشأ رابط يتضمن P12 أو كلمة مرور |
| كلمات مرور P12 داخل Core Data | Keychain مع `WhenUnlockedThisDeviceOnly`؛ ترحيل القيم القديمة عند تهيئة التخزين، واستبدال حقل قاعدة البيانات بعلامة مرجعية. لا تسجل كلمات المرور ولا تدخل HTTP |
| الشهادات والتطبيقات في Documents المكشوفة للمشاركة | ترحيلها إلى `Library/Application Support/XSignPrivate`، مع استبعاد المجلد من النسخ الاحتياطي وحماية الملفات الجديدة. Pairing ينتقل إلى المجلد الخاص أيضاً |
| خيارات مشاركة/تصدير IPA ونسخ روابطه وفتح المجلد | حذفها من Library وواجهات المصادر والإصدارات، وتعطيل File Sharing. حذف API حفظ أرشيف للمشاركة وسيرفر التثبيت القديم؛ يوجد مسار واحد مؤقت محمي بقدرة عشوائية لنقل IPA إلى iOS |
| ملف IPA يبقى في PublicStaging بعد التثبيت | حذفه بعد الاستخدام وفي مسار الخطأ؛ تسجيل أسماء UUID التي أنشأها التطبيق لإعادة محاولة تنظيفها بعد انقطاع/تحديث ذاتي. لا تُمس ملفات التطبيقات الأخرى |
| اختيار هوية غير مناسبة/خطأ غير واضح | الاحتفاظ بإعداد شهادة مرة واحدة، فحص الملفات والصلاحية ومطابقة Bundle ID بالبروفايل، والإبلاغ عن أخطاء التخزين والتوقيع بدلاً من متابعة تثبيت فاشل |

## نتائج المرحلة السابقة

البنود التالية تخص مراجعة السيرفر والتخزين السابقة. لا تُعد إثباتاً بأن مسار OTA الجديد بُني أو ثُبت على iPhone.

## نتيجة الاختبارات

- نجح بناء executable اختبارات Swift على Linux باستخدام ملفات السيرفر الإنتاجية نفسها وVapor 4.104.0 وCrypto 3.12.3 وZIPFoundation 0.9.20 المقفلة.
- نجح HTTP فعلي إلى loopback: رفض غياب المصادقة وOrigin والمحتوى غير الفارغ، قبول مهمة بلا بيانات، رفض تكرارها وعدم خدمة ملفات IPA.
- نجحت المصادقة عند تغيير المسار/المضيف/المفتاح، وحد الطابور الذي يشمل التنفيذ، والإلغاء قبل التنفيذ، وتمرير خطأ محرك العمل واستمرار الخدمة بعده. وظيفة الاختبار تستبدل توقيع IPA بعمل تجريبي؛ هذا ليس توقيع IPA فعلياً على iOS.
- نجحت ملفات IPA التجريبية: الاستيراد الصحيح، رفض traversal والمسار المطلق وbackslash وsymlink وتعارض الأسماء والملف/المجلد وCRC الفاسد وتجاوز ميزانية الفك. ملف الاختبار الخارجي بقي كما هو.
- نجح ترحيل بيانات وهمية إلى التخزين الخاص مرتين دون فقدها، ونقل Pairing وتنظيف الملفات المؤقتة ورفض التعارض دون استبدال.
- نجحت اختبارات اختيار الشهادة والنقل بكتل محدودة وفشل الكتابة/الإلغاء، واختبار C++ الفعلي لإدراج/إزالة MobileProvision.
- ملف Actions يعيد هذه الاختبارات على macOS، ثم يبني iOS ويفحص محتويات IPA قبل حفظ التعديلات. لم يتوفر Xcode أو جهاز iPhone هنا؛ تجربة Keychain وحماية الملفات والتوقيع والتثبيت الفعلي على جهاز تبقى مطلوبة.

## حدود الحماية

1. أُغلقت وسائل التصدير والتنزيل المدمجة في XSign. لا يمكن ضمان منع استخراج IPA على جهاز مكسور الحماية أو نسخة معدلة من التطبيق أو أمام شخص يملك تحكماً كاملاً بالجهاز. أثناء التثبيت يحتاج نظام iOS نفسه وصولاً لنسخة محلية؛ التنظيف بعد الاستخدام لا يلغي هذه الحقيقة.
2. روابط المصادر العامة وملفات IPA المتاحة أصلاً للعموم لا تصبح سرية بإخفاء زر النسخ. حماية الوصول إلى محتوى مصدر خاص تحتاج تحكماً فعلياً في جهة التنزيل؛ خدمة manifest لا تحمي ملفات المصدر العامة، ولم يُضف نظام اشتراكات.
3. هذا تدقيق لمسارات الطلب والفك والتخزين والتثبيت، وليس برهاناً على خلو جميع محللات Mach-O/OpenSSL أو مستوردات التعديلات من أخطاء الذاكرة. تحتاج المحركات الأصلية fuzzing ومراجعات مستمرة. لم يُدعَ أن جميع ثغرات التطبيق أُغلقت.
4. كلمات المرور التي كانت محفوظة قبل التحديث قد تبقى في نسخ احتياطية قديمة أو صفحات SQLite قديمة؛ الترحيل إلى Keychain ليس محواً جنائياً للبيانات السابقة. تغيّر هوية التوقيع أو حالة إلغاء شهادة Apple لا يُعالجان بفتح منفذ محلي.
5. قد يعلق iOS عملية XSign في الخلفية أو ينهيها. الملفات العابرة تُنظف عند تشغيله مجدداً، ومسار AFC القديم يحتفظ بتنظيفه إن استُخدم برمجياً؛ التثبيت الافتراضي لم يعد يمر به؛ لا يوجد ضمان لخدمة دائمة أو لتنظيف فوري بعد انهيار/انقطاع اتصال.
6. تُرفض الأرشيفات ذات الروابط الرمزية بدلاً من إعادة إنشائها. قد تحتاج بعض الحزم غير المعتادة إلى معالجة قبل الاستيراد. لم يُفك FairPlay ولم تُضف ميزة سحب IPA من App Store.

## مسار التثبيت الجديد بدون Pairing

- لا تستدعي واجهة التثبيت الجديدة InstallationProxy ولا تستورد Pairing. ملفات الاقتران القديمة محفوظة إن كانت موجودة، ولا تُطلب من المستخدم.
- لا يُعرض عنوان IPA أو زر تصدير؛ مسار نقل عشوائي مؤقت بطول 64 خانة، Host دقيق، لا Origin، لا query أو جسم طلب، ومدة تشغيل محدودة. يدعم HEAD ونطاقاً واحداً وطلبات الإعادة، ويحد النقل المتوازي إلى أربعة طلبات و64 محاولة للجلسة.
- يُرسل IPA بالتدفق ولا يُقرأ كاملاً إلى الذاكرة. لا يعتبر HEAD أو جزء من الملف نقلاً مكتملاً. اكتمال كل البايتات يعني تسليم الملف إلى iOS، ولا يثبت نجاح تثبيت النظام.
- الدومين يستقبل بيانات manifest فقط، ويعيد تذكرة AES-256-GCM مشفرة. لا يوقّع ولا يرفع أو يخزن IPA أو P12. توجد حدود إدخال وتذاكر ومعدلات حسب IP داخل كل instance؛ ليست حماية عالمية أو سقف تكلفة.
- تم تشغيل 6 اختبارات Node لخدمة manifest واختبار دمج إعدادات Firebase؛ نجحت. اختبارات Swift/TLS الجديدة واختبار البناء مضافة إلى Actions، ولم تُشغّل هنا لعدم وجود Swift/Xcode. تجربة تثبيت فعلية على جهاز مطلوبة.
- يجب نشر DomainBackend على الموقع الحالي والتحقق منه قبل إصدار التطبيق. workflow يفحص جاهزية الدومين قبل طلب macOS وقبل حفظ تغييرات التطبيق. لم يُنشر الدومين في هذه المراجعة. Cloud Functions تحتاج Blaze، ولا يفعّل الكود الفوترة.

التفاصيل وأوامر الدمج في [DomainBackend/README_AR.md](../DomainBackend/README_AR.md). تبقى قيود استخراج الملفات على الأجهزة المعدلة واعتماد TLS/DNS على Backloop قائمة؛ لا يوجد ضمان بمنع الاستخراج بكل الأشكال.
